# Задачи команды

Фундамент готов и выровнен по [определениям проверок жюри](genesis-fintech-checks.md):
генератор (4 типа + 2 сценария + чистые + отвлекающие), среда в протоколе жюри, `judge_adapter.py`,
matcher/награда, 4 базовые политики, траектории, файловые парные преобразования, Docker, CI,
`audit-env check` (D01–D20 + P01–P20). Ниже — оставшиеся задачи до сдачи (22.11, 23:59 Астана),
по влиянию на баллы.

## Правила работы

* Ветка на задачу: `feat/<коротко>`, `test/<коротко>`, `docs/<коротко>`; PR в `main`.
* Коммиты — Conventional Commits: `feat:`, `fix:`, `test:`, `docs:`, `refactor:`, `ci:`, `build:`, `chore:`.
* Перед PR: `make lint test check` — всё зелёное. CI повторяет это и офлайн-сборку Docker.
* **Любое изменение генерируемых данных** → поднять `ENV_VERSION` в `audit_env/version.py`, выполнить
  `make episodes trajectories` и закоммитить (CI проверяет, что `episodes/` не устарели).
* Нельзя: импортировать `audit_env.grader` из политик, читать `truth.json`/`provenance.json` вне оценщика,
  выводить эталон/пути/seed в наблюдения, ошибки или `info`.
* Протокол жюри не менять без сверки с `genesis-fintech-checks.md` и `tests/test_judge_adapter.py`.

## P0 — обязательно к сдаче

### T1. JSON-схемы (`schemas/`) — раздел 09 «схемы», блок «Контракт»
JSON Schema (draft 2020-12): `manifest`, `policy`, `ledger_row`, `invoice`, `payment`, `fx_row`, `findings`
(объект submit), `action`, `observation_reset`, `observation_step`, `truth`, `trajectory_line`.
* Тест `tests/test_schemas.py`: валидировать эпизоды из `episodes/`, наблюдения из `artifacts/*/trajectories.jsonl`
  и `findings.json` oracle. Без сети: маленький собственный валидатор нужного подмножества **или** закреплённый
  `jsonschema` только в `requirements-dev.txt` (runtime остаётся stdlib-only).
* Готово: схемы соответствуют `matcher.py`, `env.py`, `episode.py`; README ссылается на `schemas/`.

### T2. Базовые политики в отдельном процессе — блок C20, «Граница доступа»
«Простое сокрытие полей в Python-объекте не считается изоляцией». Сейчас `check` гоняет политики in-process.
* Добавить в `runner.py` режим `--isolated`: среда в процессе оценщика, политика — subprocess, обмен JSON-lines
  (политика получает только наблюдения). Oracle получает findings от оценщика заранее, как у жюри.
* Включить этот режим в `check` для закрытого прогона D01–D20; тест, что политика-процесс не имеет пути к эпизоду
  (нет аргументов/переменных окружения с каталогом).

### T3. `audit-env analyze` — критерий «Измеренный разбор сбоев»
По `grades.jsonl` + `trajectories.jsonl` строить: ложные находки по (эпизод/тип отвлекающего случая, тип находки),
пропуски по (тип, вариант), шаги/время. Писать `reports/failure_analysis.md`, подключить в `check`.
Таблица в DESIGN.md §7 сейчас посчитана скриптом вручную — заменить ссылкой на сгенерированный отчёт.

### T4. Демо — раздел 09
Запись `make demo` и `make docker-check` (asciinema/GIF) + сценарий показа в `docs/demo.md`:
reset → чтение → submit; closed-режим без награды; stdio-сервер; `check` в Docker без сети; парные проверки.

## P1 — усиливает оценку

### T5. Экспериментальная награда (отдельно от общей)
`grader/reward.py: experimental_reward(...)` — например, нормализация штрафа за шаги на число эталонных ошибок
(см. DESIGN.md §8) или частичный кредит за тип+ID без полного набора доказательств. Общая награда не меняется;
`check` и `runner` выводят обе колонки.

### T6. Больше отвлекающих случаев и вариантов — блок «Данные и эталон»
Каждый случай обязан проходить `validate_episode` (правила `rules.py` ничего не находят на чистом двойнике).
Идеи: частичный возврат; «почти дубль» (тот же клиент и сумма, другой PO); вариант `fx_conversion`
«курс на дату срока оплаты»; ошибка периода для платежа. Для каждого — пресет и строка в README.

### T7. Большие эпизоды и лимиты
Пресет `configs/large.json` (≈ 1 500–2 000 проводок, ≤ 200 документов, до 12 ошибок): генерация + прогон 5 политик
< 60 с на эпизод при `--cpus 2 --memory 4g`; тест на максимальный размер наблюдения в байтах.

### T8. Фаззинг действий
Тест: 2 000 случайных (в т. ч. некорректных) действий с фиксированным seed — среда не падает, каждый шаг
расходует бюджет, сообщения ≤ 200 символов, нет утечек (`LEAK_MARKERS` в `cli.py`).
