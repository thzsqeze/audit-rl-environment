# Задачи команды

Фундамент готов: генератор (4 типа + 2 сценария + чистые + отвлекающие), среда, matcher/награда,
4 базовые политики, траектории, Docker, CI, `audit-env check`. Ниже — оставшиеся задачи до сдачи
(22.11, 23:59 Астана), отсортированные по влиянию на баллы.

## Правила работы

* Ветка на задачу: `feat/<коротко>`, `test/<коротко>`, `docs/<коротко>`; PR в `main`.
* Коммиты — Conventional Commits: `feat:`, `fix:`, `test:`, `docs:`, `refactor:`, `ci:`, `build:`, `chore:`.
* Перед PR: `make lint test check` — всё зелёное. CI повторяет это и сборку Docker.
* **Любое изменение генерируемых данных** → поднять `ENV_VERSION` в `audit_env/version.py`,
  перегенерировать `make episodes trajectories` и закоммитить (CI проверяет, что эпизоды не устарели).
* Нельзя: импортировать `audit_env.grader` или `_grader/` из политик; выводить эталон в наблюдения/ошибки.

## P0 — обязательно к сдаче

### T1. JSON-схемы (`schemas/`) — критерий «Контракт», раздел 09 «схемы»
Файлы JSON Schema (draft 2020-12): `manifest`, `policy`, `ledger_row`, `invoice`, `payment`, `fx_row`,
`findings` (submit), `action`, `observation`, `truth`, `trajectory_line`.
* Тест `tests/test_schemas.py`: валидировать сгенерированные эпизоды, наблюдения из траекторий и
  `findings.json` oracle. Без сети: свой маленький валидатор подмножества схем **или** закреплённый
  `jsonschema` только в `requirements-dev.txt` (runtime остаётся stdlib-only).
* Готово, когда: схемы соответствуют коду (`audit_env/grader/matcher.py`, `env.py`, `episode.py`), тест зелёный.

### T2. Загрузка эпизода из каталога — проверка жюри на файлах
`AuditEnv.reset(seed, config)` сейчас генерирует в памяти. Нужно:
* `Episode.load(dir)` (обратный к `Episode.write`, включая `null` в CSV) и
  `AuditEnv(...).reset_from_dir(path)` / `audit-env run --episodes-dir episodes/dev`.
* Тест: `write → load` даёт идентичные `public()` и `truth`; oracle на загруженном эпизоде = 1.0.

### T3. Файловые «безвредные преобразования» для парных проверок (15 баллов)
Скрипт `audit-env transform --in <ep_dir> --out <dir> --seed N`: переименовать все ID (row/journal/doc/
invoice/payment/entity) согласованно во всех файлах, включая `truth.json`, и перемешать строки.
* Тест: для 20 эпизодов oracle-награда и `rules_auditor`-награда до/после совпадают;
  `validate_episode` чист. (Внутри генератора это уже есть через `id_salt` + `shuffle_rows`,
  нужна версия, работающая на файлах так, как это сделает жюри.)

### T4. Отчёт о сбоях — критерий «Инженерия: измеренный разбор сбоев»
Команда `audit-env analyze --run runs/<x>`: по `grades.jsonl` + траекториям строит таблицы
FP по `(type, finding_status)` и FN по `(type, variant)` (см. DESIGN.md §7, там пока посчитано вручную),
пишет `reports/failure_analysis.md`. Подключить в `check` (секция `failure_analysis`).

### T5. Демо
Запись `make demo` (asciinema или GIF) + 1 страница сценария показа: reset → чтение → submit, eval-режим
без награды, stdio-сервер, `check` в Docker без сети. Положить в `docs/demo.md`.

## P1 — усиливает оценку

### T6. Экспериментальная награда (показывать отдельно от общей)
`grader/reward.py: experimental_reward(...)` — например, частичный кредит за верный тип+ID без полного
набора доказательств, или нормализация штрафа за шаги на число эталонных ошибок (см. ограничение в
DESIGN.md §8). Общая награда не меняется; `check` выводит обе колонки.

### T7. Больше отвлекающих случаев и вариантов (оценка «Данные и эталон»)
Каждый новый случай должен проходить `validate_episode` (правила в `rules.py` ничего не находят на чистом
двойнике). Идеи: частичный возврат; «почти дубль» (тот же клиент и сумма, другой PO);
платёж в иностранной валюте за счёт в другой валюте; вариант `fx_conversion` «курс на дату оплаты счёта».

### T8. Стресс и лимиты
Пресет `configs/large.json` (≈ 2 000 проводок, 200 документов, 12 ошибок): генерация + прогон 5 политик
< 60 с на эпизод при `--cpus 2 --memory 4g`; тест на максимальный размер наблюдения (байты).

### T9. Фаззинг действий
Тест: 2 000 случайных (в т. ч. некорректных) действий с фиксированным seed — среда не падает, каждый шаг
расходует бюджет, сообщения ≤ 200 символов, нет утечек (`LEAK_MARKERS` из `cli.py`).
